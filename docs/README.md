# 文档维护规则

## 职责划分

- `docs/features/index.md` 是功能清单，由功能文档头部字段生成，不手改；名称列用于按语义定位文档。索引负责覆盖率。
- `docs/features/FTR-NNN.md` 只描述一个可独立验收的功能：行为、接口与代码映射、约束与失败行为、验收与测试；映射中的 `路径:符号` 必须在代码里真实存在，验收条目必须锚定测试文件中真实存在的符号。功能文档负责可理解性。
- `docs/decisions/` 存放跨功能、影响长期维护的 ADR；被取代时保留旧记录并标记 `superseded`。
- `docs/templates/` 提供新建文档的骨架，模板中的占位符必须全部替换。

## 新增或修改功能

1. 分配或复用 `FTR-NNN`，避免 ID 重复。
2. 按 `docs/templates/feature.md` 创建或更新功能文档，写入真实代码、测试路径与关键符号。
3. 运行 `python scripts/gen_feature_index.py` 重建索引，索引不手改。
4. 修改代码和测试后运行 `python scripts/check_docs.py`。

## 拆分与删除

- 文档触及长度上限时拆分真正独立的功能，不要单纯删掉关键约束。
- 移除功能时，同一变更中删除或归档文档并更新索引，确认调用方、数据迁移与兼容性影响。
- 跨功能取舍记录为 ADR，使用 `docs/templates/adr.md`。

## 发布规则包

运行 `python scripts/package_rules.py` 生成 `dist/agent-maintainability-rules.zip`。产物只含规则、门禁脚本、模板与工作流，不含本项目的功能文档与示例代码，索引在打包时重建为空。脚本按固定顺序与时间戳打包，并在解压后重跑索引检查、文档门禁与自测；任一项失败则不产出产物。

## 原则

索引负责覆盖率，功能文档负责可理解性，测试负责行为验证，代码是运行行为的最终事实来源。四者不一致时必须在合并前修复。
