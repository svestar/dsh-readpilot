# ADR-006：书库分类使用按书标签

- **状态：** accepted
- **日期：** 2026-11-02
- **范围：** FTR-013

## 背景

书库原来只有按扫描顺序排列的平铺网格，无法整理，也没有“最近阅读”入口。书籍文件由用户维护，阅读器不应移动、重命名或改写原文件；分类还需要跨刷新保留。

## 决策

1. 分类采用**自定义标签**：一本书可属于多个标签，标签不改变目录结构。
2. 标签存到 `$DSH_HOME/dsh-readpilot/library-meta.json`，结构为 `{ tags: { [bookId]: string[] } }`；新增 `libraryMeta` 与 `setBookTags` RPC。
3. 最近阅读直接由现有 `progress.updatedAt` 计算，不新增“已读”状态或历史表。
4. 客户端用 `filterBooks`、`recentBooks`、`tagCatalogue` 做分类、搜索、排序和标签计数。
5. 标签文件损坏或条目非法时回退空标签，不阻塞书库；每本书最多 20 个标签，每个 1–24 字。

## 备选方案

- 固定书架/文件夹：一本书只能属于一个分类，且需要移动文件或额外映射，放弃。
- 写入书籍文件元数据：会修改用户文件，且各格式支持不一致，放弃。
- 只存 `localStorage`：换浏览器/设备丢失，且与书库工作区不一致，放弃。
- 增加“已读”字段：当前只有章节进度，没有完成判定，暂不引入。

## 后果

收益：书库可多标签整理，最近阅读直接复用进度，不改原文件；标签数据与书库工作区一起持久化。

代价：`bookId` 由文件真实路径生成，移动或改名后旧标签不会自动迁移；标签只保存在当前 DSH 数据目录，不随书籍文件传播；最近阅读只反映有进度的书，无法区分“读完”。

验证：标签存储与边界单测、分类/排序/最近阅读单测；书库页面手工验证标签编辑、筛选和最近阅读跳转。
