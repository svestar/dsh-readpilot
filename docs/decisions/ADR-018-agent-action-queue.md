# ADR-018：Agent 动作的内存队列与客户端轮询

- **状态：** accepted
- **日期：** 2026-11-08
- **范围：** FTR-043

## 背景

阅读器的当前书、章节、分页和 UI 状态只存在于客户端；Host 工具无法直接调用客户端 `selectChapter` 或重载批注。现有工具是只读的，Agent 只能描述“打开/跳转”，不能真正改变界面。需要一个不依赖未验证宿主事件通道、且能在主阅读与侧栏阅读同时存在时去重的桥。

## 决策

1. Host 维护进程内动作队列（TTL 120 秒、最多 100 条）；工具入队并返回 `actionId` 与 `queued` 回执。
2. 客户端主阅读与侧栏阅读每秒调用 `readerActions.take`；动作取出即从队列移除，先到先执行，避免双阅读器重复。
3. `take` 支持按类型与书过滤：`notesRefresh` 只被当前书匹配的阅读器取走；`libraryRefresh` 由主阅读处理；导航动作任一阅读器可取，跨书时打开侧栏。
4. `reader_mark`、`reader_tag`、`reader_status` 的**数据**由 Host 立即写入，队列只负责队列化 UI 刷新；`reader_goto`、`reader_open_panel` 是纯导航动作。
5. 动作不持久化；Host 重启或超时后未取走的动作丢失，工具回执只表示“已入队”。

## 备选方案

- 依赖宿主事件总线推送：延迟最低，但当前客户端服务没有稳定的事件 API，无法验证。
- 工具结果卡上的“执行”按钮：实现简单，但需要用户逐次点击，不满足 Agent 动作。
- 持久化动作文件：跨重启可靠，但需要文件锁、清理和幂等，超出当前需求。
- WebSocket/轮询每个读者会话：隔离更细，但需要宿主通道与连接生命周期管理。

## 后果

收益：不改 Host 事件协议即可让 Agent 驱动界面；写入与刷新分离，重复轮询安全；主/侧栏共用一条队列。

代价：最多约 1 秒延迟；没有阅读器时动作等待并可能超时；队列不跨重启；动作不可撤销（RDM-004）；轮询产生固定 RPC 开销。

验证：队列过滤与取出（`reader_actions_take_filters_and_removes`、`reader_actions_take_all_returns_every_type`）；`reader_goto` 入队与回执（`tools_read_bounded`）；真实宿主的主/侧栏轮询仍需手动回归。
