# ADR-019：动作回执与逆操作撤销

- **状态：** accepted
- **日期：** 2026-11-08
- **范围：** FTR-043、FTR-044

## 背景

Agent 的写动作直接修改批注、长笔记、标签和状态，工具只返回“已保存”，没有统一撤销入口。客户端无法从工具结果推断旧值，因此逆操作必须由 Host 在写入前捕获。

## 决策

1. Host 在内存中保存写动作回执，包含摘要、书 id、时间、是否可撤销与一个逆操作描述。
2. 逆操作使用结构化描述而不是回调：删除批注、恢复批注快照、恢复长笔记文件、恢复标签、恢复状态。
3. 新增批注的逆操作是删除；重写/删除批注保存完整旧记录；删除长笔记保存原文件记录与正文；标签/状态保存旧值。
4. 客户端轮询当前书回执；阅读栏提供“操作历史”入口，弹窗列出回执并逐条提供“撤销”按钮，不使用 Toast。
5. 导航动作（goto/open_panel）不改数据，不生成可撤销回执；不可提供逆操作的写动作不应加入。
6. 回执不持久化，TTL 10 分钟、最多 100 条；撤销成功后标记 `undoneAt`，不再重复提示。

## 备选方案

- 客户端保存撤销栈：无需 Host 回执，但客户端看不到 Host 工具写入的旧值和长笔记文件。
- 持久化操作日志：跨重启可靠，但需要清理、幂等、冲突和隐私处理，超出当前范围。
- 通用文件快照/事务回滚：覆盖所有动作，但写放大与并发冲突成本高。
- 不做撤销，只提供历史：实现最少，但不满足“一键撤销”。

## 后果

收益：写动作可逆且用户可见；撤销数据与 UI 刷新统一走现有动作队列；长笔记删除可恢复原 id/文件名。

代价：回执只活 10 分钟，Host 重启丢失；撤销是最后写入者胜出，可能覆盖用户随后手动修改；长笔记恢复遇到同名文件会失败；导航不可撤销；回执占用内存。

验证：回执列出/标记撤销（`reader_receipts_can_be_listed_and_marked_undone`）；批注与长笔记删除后撤销（`tools_read_bounded`）；真实历史入口/轮询仍需手动回归。
