# ADR-023：Kindle 文件只提示转换为 EPUB

- **状态：** accepted
- **日期：** 2026-11-10
- **范围：** FTR-048

## 背景

用户在书库中放入 MOBI、AZW、AZW3 时，当前扫描会直接忽略，既看不到文件，也不知道如何处理。原生解析需要维护 Kindle 容器、目录、锚点和 DRM 边界，成本高；用户明确只需要转换提示。

## 决策

1. 扫描识别 `.mobi`、`.azw`、`.azw3`，以 `format: 'kindle'`、`supported: false` 列入书库。
2. 书库卡片显示“需转 EPUB”徽标；打开时不进入阅读器，只显示“请先转换为 EPUB”。
3. 不提供 Calibre 步骤、外部转换器调用或自动转换；不解析 Kindle 文件，不处理 DRM。
4. 保留 contentKey 计算以维持书库身份/去重；不解析章节、封面、目录或文本。
5. 其他格式和既有阅读路径不变；检索跳过不支持的书。

## 备选方案

- 原生解析 MOBI/AZW3：支持最完整，但容器、字体、锚点和 DRM 成本高，且格式正在退场。
- 直接忽略：实现最少，但用户不知道文件被跳过。
- 自动调用 Calibre：体验更顺，但引入外部依赖、路径、版本和失败处理，超出当前需求。
- 包含转换步骤：用户明确不需要，提示保持最小。

## 后果

收益：用户能看到 Kindle 文件并知道下一步；不增加解析依赖；不会误把不可读文件当损坏。

代价：Kindle 图书不能搜索、批注、摘要或阅读；用户必须自行转换；扩展名识别可能误判；contentKey 仍需读取文件首尾块。

验证：Kindle 扫描为不可读（`scan_lists_kindle_files_as_unsupported`）；打开返回不支持（`kindle_book_is_listed_but_not_opened`）；真实转换流程需用户手动验证。
