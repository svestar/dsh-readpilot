# ADR-013：本地 JSON 写入串行化

- **状态：** accepted
- **日期：** 2026-11-05

## 背景

设置、进度、会话、书库元数据与短笔记都以单个 JSON 文件保存。写入采用「读出整表 → 修改 → 写回」，临时文件加 rename 只保证单个文件不撕裂，不能防止两个并发请求互相覆盖：后写者用旧快照覆盖先写者，且不会报错。

DSH 中同一进程可以并发调用工具，用户也可能同时开多个面板；这类丢更新会直接丢失阅读进度或笔记。

## 决策

在 Host 进程内为每个逻辑文件维护一条 promise 队列（`enqueueWrite(key, task)`）：

- 键相同的任务串行执行，键不同的任务仍可并发；
- 前一个任务失败不会阻断后续任务；
- 队列只存在于内存，进程退出即丢弃。

接入范围：

- `notes.ts`：短笔记的 add/update/remove，键为笔记文件路径；
- `library-meta.ts`：标签、状态、评分，键为 `library-meta.json`；
- `api.ts`：阅读进度与会话映射，键为 `progress:<dataDir>`、`sessions:<dataDir>`。

## 后果

正常路径没有额外依赖与延迟，只在真正并发时排队；同一本书的连续写入按到达顺序落盘。

限制：

- 只覆盖单进程。两个 DSH 进程或两个窗口分别加载插件时，仍可能互相覆盖，需要文件锁才能彻底解决。
- 队列不持久，进程崩溃时正在排队的写入会丢失；调用方仍以 `await` 的返回值为准。
- 长笔记文件、草稿与记忆设置目前未接入；它们的写入频率低，后续按同一模式补充。

## 备选方案

- 文件锁（`proper-lockfile` 等）：能跨进程，但引入依赖与陈旧锁问题，当前单进程场景收益不足。
- 内嵌数据库（SQLite）：彻底解决并发与迁移，但对一个本地阅读插件来说过重。
- 只读 + 追加日志：改动面大，且与现有 JSON 快照格式不兼容。
