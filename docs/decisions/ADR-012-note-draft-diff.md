# ADR-012：笔记草稿-差异-应用

- **状态：** accepted
- **日期：** 2026-11-03
- **范围：** FTR-005、FTR-008、FTR-020、FTR-022

## 背景

用户要求笔记默认由读者写，只有读者明确要求时伴读才写，且每次 agent 写入都要先看 diff。若伴读会话保留通用文件写权限，它可以绕过阅读器工具直接改 `notes/`，diff 只能事后发现。笔记是用户文稿，静默覆盖不可接受。

## 决策

1. 伴读会话使用 `read-only` 沙箱（ADR-009），通用 `write`/`edit`/shell 不能写工作区。
2. 新增 `reader_notes` 工具（`index`、`read`、`create`、`write`、`append`）。写操作只生成草稿，落到 `$DSH_HOME/dsh-reader/drafts/<bookId>/<draftId>.json`，不碰正式文件；返回草稿 id、目标笔记与字数。
3. UI 展示行级 diff：新建为全文预览，追加为新增行，替换为统一 diff；预览只读，需要修改时拒绝草稿后让伴读重新生成，或应用后在编辑器修改。用户应用时 Host 校验 `baseHash`，不匹配则提示冲突，允许重放或手动合并；拒绝删除草稿。
4. 应用前把旧内容快照到 `.history/<noteId>/<时间戳>.md`，保留最近若干份；撤销是用户动作，应用快照。
5. 草稿与正式文件都只由 Host 写；UI 通过 RPC 读取草稿、应用与拒绝。用户在编辑器里的手动保存不走 diff。
6. 整书综述这类跨多章任务可由伴读调用子 agent 生成草稿，但落盘仍走同一 apply 流程。
7. 记忆更新不走本流程：记忆是 agent 状态，同意后自动更新，只留 changelog 与撤销（ADR-011）。

## 备选方案

- 直接写文件加提示词约束：实现最简单，但无法保证 diff，agent 可以用通用工具绕过。
- 只在对话里输出内容，用户手动复制：没有覆盖风险，但没有草稿、冲突与历史，长笔记体验差。
- 每次写入都弹工具审批：能拦住，但没有 diff 预览与编辑，且审批 UI 不承载长文。
- 把笔记放到工作区外：能硬隔离，但违背“可见 notes/”。

## 后果

收益：agent 写入事前可见、可编辑、可撤销；用户文稿不会被静默覆盖；冲突可检测。

代价：依赖 `read-only` 能按会话设置（ADR-009 的 P0 验证）；草稿需要持久化与清理；UI 需要轮询或在会话空闲时刷新；同一本书两个 occurrence 时草稿提示可能重复；用户可能用外部编辑器改文件，apply 时冲突。

验证：只读下通用写入被拒；create/append/replace 三种 diff；预览编辑；baseHash 冲突；拒绝清理；历史撤销；子 agent 草稿；刷新后草稿仍在。
