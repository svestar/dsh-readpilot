# ADR-022：扫描版 PDF 以原版图片降级阅读

- **状态：** accepted
- **日期：** 2026-11-10
- **范围：** FTR-047

## 背景

PDF 解析依赖文本层；扫描版没有文本项时，`open` 直接报“需要 OCR”，用户即使只想翻页查看也无法进入阅读器。现有 PDF 视觉渲染已经能按页输出图片，缺少的是无文本时的能力降级和 UI 约束。

## 决策

1. PDF 解析结果增加 `pageCount` 与 `scanOnly`；没有可提取章节但页数大于 0 时标记扫描版。
2. `open` 对扫描版返回 `supported: true`、`scanOnly: true`、合成目录项 `scan`（第 1 页）和页数，不再抛错。
3. 客户端进入原版 PDF 视觉阅读，只提供逐页、页码跳转与缩放；搜索、书签、重排、划选批注、提示词、摘要和伴读引用禁用。
4. Header 隐藏搜索/书签入口，快捷键拦截 search/bookmark；设置隐藏来源与字号；阅读界面不显示额外提示，限制说明放在帮助手册。
5. 不引入 OCR、云识别或图片转文本；有文本层的 PDF 保持原行为。

## 备选方案

- 引入 OCR：能恢复文本功能，但依赖外部引擎、语言包、性能和隐私成本，超出当前范围。
- 仅报错并提示用户转换：实现最少，但用户无法直接查看扫描版。
- 允许打开但不限制功能：搜索和批注会静默失败或产生错误定位，体验更差。
- 自动把图片页转成文本：同样需要 OCR，且会引入不可信的文本层。

## 后果

收益：扫描版可直接查看和翻页；有文本 PDF 不受影响；不新增依赖。

代价：扫描版只能原版阅读，不能搜索、批注、摘要或引用；页面渲染有内存与时间成本；页数上限沿用 PDF 限制；阅读进度只能按页码百分比近似恢复；需要额外 UI 提示和功能禁用。

验证：无文本 PDF 标记扫描版（`parse_pdf_without_text_returns_no_chapters`）；扫描版能力矩阵（`scan_only_pdf_has_no_text_reflow`）、visual-only 打开（`open_scanned_pdf_returns_visual_only`）；真实扫描文件的主/侧栏视觉阅读仍需手动回归。
