# ADR-027：角色卡分层与身份注入

- **状态：** accepted
- **日期：** 2026-11-26
- **范围：** FTR-017、FTR-023、FTR-057、FTR-059

## 背景

角色/风格卡原先是 `memory/role.md` 中的一张跨书记忆卡，受全局记忆开关控制，并被描述为回答风格参考。用户实际期望写入人物设定后，伴读以该人物身份、知识边界和思考方式回应；同时不同书需要不同角色，不能让“音乐老师”指导数学。`AGENTS.md` 中的“你是 DSH 阅读器中的阅读助手”也会与自定义人物冲突。

## 决策

1. 角色卡从记忆拆为独立模块与右侧栏“角色”页，不再受记忆开关控制，有自己的全局启用开关与每书“使用独立角色”开关。
2. 解析顺序固定为：本书角色（开关开启且非空）> 全局角色（非空）> 默认角色“DSH 阅读助手”。只注入生效的一层，不叠加；角色只对绑定书的会话注入，无书会话不注入角色块。
3. 默认身份从 `AGENTS.md` 移到角色模块；`AGENTS.md` 只保留工具地图、阅读边界与通用原则。无自定义角色时，绑书会话由 `<reading_role>` 注入默认身份；无书会话不注入。
4. 角色使用独立的 `dsh-readpilot:role` 上下文，order 在守卫与阅读上下文之前，预算约 1200 字；角色卡是用户设定的扮演指令，伴读直接以第一人称回应，不声明在扮演，默认身份让位于角色；角色背景与知识边界只塑造风格，不得妨碍任务与工具执行；只有用户明确询问真实身份、要求退出，或人设与系统/权限规则冲突时才说明真实身份。角色不能覆盖系统规则、工具权限或用户当前要求。
5. 存储改为 `roles/global.md` 与 `roles/<bookId>.md`，历史与撤销复用通用卡片存储；旧 `memory/role.md` 首次读取时迁移为全局卡，旧文件保留。
6. `reader_memory` 移除 `role` scope，只管理本书卡与读者卡；角色只能通过角色页编辑，避免记忆工具与角色设定语义混杂。

## 备选方案

- 继续放在记忆页：开关语义混杂，用户会误以为角色是记忆数据。
- 只做全局角色：无法按书切换学科/人物。
- 把角色直接写进 `AGENTS.md`：静态、工作区级，切换角色要改文件，且无法按书覆盖。
- 角色与记忆同时注入：全局角色与本书角色会互相冲突。

## 后果

收益：角色可复用、按书覆盖、独立开关；默认身份稳定；记忆页回到两张卡；角色上下文不与阅读/笔记预算竞争。

代价：新增角色模块、RPC、页面与迁移路径；工具 schema 移除 `role` scope 属破坏性变更；用户需要理解“全局角色 / 本书角色 / 默认角色”的优先级。

验证：优先级、关闭回落、旧数据迁移、按会话注入、角色页来源显示与历史确认由 FTR-059 的测试覆盖。
