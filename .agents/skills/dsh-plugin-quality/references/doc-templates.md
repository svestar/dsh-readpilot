# 文档模板

## FTR

```markdown
# 功能名称

- **ID：** FTR-NNN
- **名称：** 功能名称
- **状态：** active
- **代码：** `src/path.ts`（入口符号）
- **测试：** `tests/path.test.ts`

## 行为

写触发条件、输入输出、可观察结果和边界；不写实现流水账。

## 接口与代码映射

| 入口/符号 | 位置 | 职责 |
|---|---|---|
| `symbol` | `src/path.ts:symbol` | 职责 |

## 约束与失败行为

写权限、上限、错误码、并发和兼容性。

## 验收与测试

- 正常路径：可观察结果（`test_symbol`）。
- 边界：失败行为（`test_symbol`）。
```

## ADR

```markdown
# ADR-NNN 标题

## 背景

要解决的问题、约束、已经排除的方案。

## 决策

选了什么，边界在哪里。

## 后果

需要接受的代价、后续要做的事、什么时候需要重审。
```

## 功能索引行

```markdown
| `FTR-001` | 名称 | `docs/features/FTR-001-slug.md` | `src/path.ts` | `tests/path.test.ts` | active |
```

表头固定为：

```markdown
| ID | 名称 | 文档路径 | 代码路径 | 测试路径 | 状态 |
```

## 路线图

```markdown
| ID | 功能 | 解决什么问题 | 验收线索 | 优先级 | 排期 | 状态 |
|---|---|---|---|---|---|---|
| RDM-001 | 候选名称 | 痛点 | 怎么算做完 | 高 | 未排期 | candidate |
```

落地后删除该行，新建 FTR 并登记索引。
